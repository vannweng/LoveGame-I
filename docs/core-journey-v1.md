# 核心旅程第一版

本輪依使用者確認，先交付三種投入路線、真實重要日任務、篇章收藏與下次回顧。改期、替代任務及相關計分規則尚未定義，不在這一版實作。

## 已完成的可操作流程

1. 在關係資料設定生日、交往日、結婚日或自訂日期。
2. 首頁依事件日期呈現重要日；尚未結束的舊篇章仍保留，不會跨年消失。
3. 選擇路線：輕量心意（確認行程）、剛剛好（禮物／卡片／行程）、完整企劃（五個模板）。
4. 開始時快照事件、路線、任務規則與偏好；之後修改個人設定不回溯改變既有篇章。
5. 開放前不能結算；開放後依原有 Success／Late／Fail 期限記錄結果，不額外修改 EXP／Combo／Rank 規則。
6. 所有任務結算後，自動保存「事件準備手記」，包含每步結果、事件日期與路線；心得選填且可日後修改。
7. 同一來源的重要日下一年度開啟時，呈現上次已結束篇章的心得。不使用 AI，也不根據心得推斷伴侶情緒。

篇章收藏不必等到 GG 才能取得。遺物以完整篇章作為唯一資料來源，不另外複製一份可能失去同步的收藏文件；收藏頁保留既有稱號與輪迴紀錄入口。

## 儲存與一致性

- 本轮仍是 **本機原型**，不是正式雲端版本。
- `JourneyRepository` 是新旅程讀寫邊界；目前實作為 `LocalJourneyRepository`。
- `lovegame:journey:{userId}` 保存 schema version 1、遊戲進度、篇章、收藏、Run History 與日常活動。新旅程首次建立時承接舊進度與活動，不清除舊 key。
- 任務結果、獎勵、收藏、輪迴與篇章狀態在同一份存檔一起保存。應用服務依序執行讀取、更新、寫入，避免同一執行個體快速重複點擊發獎。
- 日常／週末活動與其 EXP 同樣納入單次保存，避免完成已落盤、獎勵卻未保存的中間狀態。
- 載入時還原任務與收藏的 Date。未知 schema 拒絕讀取，不覆寫。
- DEV 情境改為隔離的記憶體旅程，不寫入真實旅程；結束預覽後重新載入原存檔。DEV 登出僅清除登入狀態，不清除設定與故事。
- 任務提醒經 service adapter 排程／取消；已結算任務取消提醒，通知點擊可開啟對應篇章任務。Web 沒有原生通知能力。

## 時間與結算限制

本機原型按裝置時區建立日期邊界，依回報時刻判定。沒有背景自動結算：逾期任務會保留，玩家開啟後可記錄未趕上。

正式版本仍必須由 server time／save timezone 成為權威。不可將本機篇章結果直接視為可信雲端寫入。需要另外完成 Journey Firestore adapter、server 篇章快照／封存／歷史交易、重生／日常獎勵交易、migration 與跨裝置整合。

本輪既有 Cloud Functions 修正：

- 查重改用 `occurrenceKey`（日期來源＋發生日＋模板），避免生日與紀念日在同年互相擋住。
- `generationKey` 同步採用來源完整的格式；已具備 occurrenceKey 的舊文件可沿用查重。
- normal 任務不增減 Rank；-10 正確寫入 `gg`。
- client／server 所有結果、重要性、Rank 邊界的對照測試已補齊。

## 本輪沒有宣告完成的項目

- Firebase 正式部署、遠端推播、正式 Analytics、跨裝置同步。
- 改期、替代任務、更多情境路線、由歷史自動修改任務、故事分享卡。
- Android 實機的通知、背景恢復與儲存容量驗證。
- 既有無 occurrenceKey 的更早期雲端資料遷移（若存在，需上線前盤點）。

## 驗證

單元測試涵蓋三條路線、同年多事件、跨年／閏日、期限邊界、一次性結算、成功／失敗封存、心得延續、存檔還原與保存失敗後重試。

以隔離瀏覽器資料完成手機寬度 Web 操作：開始生日篇章 → 輕量心意 → 完成行程 → 保存心得 → 重新整理 → 回看心得與完成結果，確認 EXP 只增加一次且無執行錯誤。

Firestore Emulator 測試需 Java 21。本機現有 Java 17，故本輪未通過 Emulator gate；不得將纯函式測試通過描述為後端整合已驗收。
